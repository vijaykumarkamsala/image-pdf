# Recovery 2A Contract Reconciliation

**Status:** Implemented decision record
**Date:** 30 August 2026
**Authority:** `PRODUCT_V2_CONSOLIDATED_IMPLEMENTATION_AUTHORITY.md`, section 21

## Reconciled baseline

Recovery 1 established shared benchmark/Product contracts at schema version
`1.6.0`, a NestJS shell, a React shell, production Python boundaries and strict
POC-to-production dependency gates. That baseline remains valid evidence.

The following material contradictions were resolved before Recovery 2A contract
work:

| Recovery 1 or older state | Recovery 2A authority | Resolution |
| --- | --- | --- |
| Product contracts shared the benchmark `v1` version and generator. | Production contracts must evolve without changing benchmark identities. | Add independent version `1.7.0` under `packages/schemas/product-v1/`; preserve all `v1` schemas and canonical vectors. |
| `Project` also represented collections and subprojects through a kind enum. | Collections, projects and subproject relations require explicit production concepts. | Add `Collection`, `ProjectRecord`, `CollectionProjectRelation` and parent-project metadata without removing the Recovery 1 type. |
| `AssetOriginal.project_id` implied storage location on immutable identity. | Canonical location is mutable while original/source identity and reusable references remain stable. | Add immutable `AssetOriginalRecord`/`SourceVersionRecord`; put canonical location only on `WorkspaceFile`; store project/document reuse in `ReusableFileReference`. |
| `ProductError` was not the API shell's actual response. | One standard typed customer-safe error envelope is required. | Add `ErrorEnvelope` and return it from the NestJS global filter without internal exception text. |
| API readiness described database/object storage as deferred. | Recovery 2A requires PostgreSQL repositories and deterministic local object references. | Add a PostgreSQL 17 repository and metadata-only object-reference catalog; keep customer bytes out of the relational database. |
| React routes were static placeholders and API transport always threw. | Projects and Files foundations must consume real NestJS APIs. | Replace shell placeholders with bootstrap, workspace, Projects and Default Files journeys backed by `/v1`. |
| Earlier POC/root wording constrained implementation to benchmark tasks. | Consolidated V2 authority is highest product authority. | Root `AGENTS.md` remains the V2 authority-aligned version from Recovery 0; earlier POC documents remain historical evidence only. |

## Compatibility decision

- No Recovery 1 model, `packages/schemas/v1` artifact, canonical vector or POC
  schema-export file is changed.
- Product-kernel schemas and TypeScript are generated by
  `tools/generate_product_contracts.py`.
- `ipw-contracts-ts/product` exposes only the production product-kernel types,
  avoiding benchmark runtime dependencies in the NestJS build.
- All new changes are additive. No destructive migration or contract break is
  introduced.

## Remaining non-contradictions

Legacy UI, benchmark runner, processors, PDF/vector code, model files and worker
boundaries remain quarantined or unchanged. Responsive web is the only customer
surface in Recovery 2A; no native application workspace exists.
