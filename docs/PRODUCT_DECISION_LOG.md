**Version:** 0.1  
**Date:** 24 August 2026  
**Purpose:** Preserve decisions and rationale so later AI agents do not reopen settled questions or misinterpret brainstorming as final scope.

| D-038 | Licence gates bind to run purpose, not to model download. Commercial clearance is required for public demo, staging and production; local research and internal benchmark runs are permitted for any disposition except blocked, provided results are marked. | Evaluating a model to decide whether to pursue a licence is normal internal research use. Requiring clearance first would mean negotiating terms for models of unmeasured quality. Refines D-013 rather than replacing it. | Approved 24 Aug 2026; see ADR-0002 |
| D-039 | Security and supply-chain checks (official source, pinned commit, verified weight hash, safetensors preferred, no inference-time network, container isolation) remain mandatory from day 1 at every purpose level. | Loading a pickled checkpoint is arbitrary code execution on a developer machine. That risk is identical before and after shipping and is unrelated to commerce. | Approved 24 Aug 2026 |
| D-040 | Every advertised Release 1 operation must retain at least one `approved` candidate in its shortlist. | The real risk of deferring commercial clearance is sunk-cost anchoring on a non-commercial winner. This makes a licence negotiation an upgrade, never a rescue. | Approved 24 Aug 2026 |
| D-041 | Adopt a monorepo layout (`apps/`, `services/`, `packages/`, `data/`, `infra/`) with a `workspaces.toml` manifest declaring each workspace's lifecycle stage. Supersedes the Repository Shape section of AGENTS.md. | POC-005 adds TypeScript and POC-006 adds Docker; the flat `poc/` shape has no room for either and no mechanism to keep production code from importing POC code. Cheapest to do before any of that exists. | Approved 24 Aug 2026; see ADR-0002 |
| D-042 | Monorepo structure without orchestration tooling: npm workspaces and pip/venv now; no Nx, Turborepo, pnpm or uv until a measured need appears. | Every tool is a prerequisite a reviewer must install before verifying the work, and a licence-register entry. The full check suite runs in ~12 seconds, so build orchestration has no current payoff. | Approved 24 Aug 2026 |
| D-043 | Inspect images by parsing headers, not by decoding. No imaging library enters the repository until POC-004. | POC-003 requires excessive dimensions to be caught *before unsafe allocation*; a library that decodes first has already allocated. Header parsing settles dimensions, depth and channels from a few hundred bytes, so no decode-bomb surface exists at all, and the runtime licence register stays at one entry. | Approved 24 Aug 2026; see ADR-0003 |
| D-044 | "Normalize orientation metadata" means deriving the transform and true display dimensions, not rotating pixels. | Rotating would require decoding and writing, and writing an original is forbidden by D-006. Pixel application is a POC-004 processing step. | Approved 24 Aug 2026; see ADR-0003 |
| D-045 | Adopt both Pillow and libvips as standard-processing engines behind one processor contract, rather than choosing one. | The deterministic baseline then carries its own performance comparison. First measurement: libvips uses ~17x less memory on a 64x64 resize, the property POC-012 tiling and the 100 MB professional path depend on. | Approved 24 Aug 2026; see ADR-0004 |
| D-046 | Golden outputs are compared by exact SHA-256, not pixel tolerance, with a documented regenerate-and-review procedure for version bumps. | A tolerance survives a genuine resampling regression of the same magnitude it was set to ignore, and detecting that is what the benchmark exists for. Silent drift in a measuring instrument is worse than a failing build. | Approved 24 Aug 2026; see ADR-0004 |
| D-047 | libvips (LGPL-2.1) is approved for server-side use with recorded notices, subject to a MANDATORY re-review before any native desktop or mobile application is distributed. | LGPL obligations attach on distribution; a hosted service distributes no binaries, so the duty is notice and attribution only. A native app (blueprint section 23) would trigger relink and source-availability duties. Pillow remains the D-040 approved fallback, so the condition is survivable. | Approved 24 Aug 2026; re-review deferred; see ADR-0004 |
| D-048 | All identifiers, labels and configuration values must be named as production would name them, not scoped to the POC. Task and lifecycle-stage fields remain as provenance. | Identifiers reach run digests, the licence register and production configuration. Renaming one after it has been recorded in a content-addressed digest makes every prior run incomparable. Fixed a live instance: the standard baseline was 'standard-pillow' in the processor and 'deterministic-baseline' in the register. | Approved 24 Aug 2026 |
| D-049 | The browser lab uses no bundler and no test framework: tsc plus an import map, with Node's built-in test runner and native TypeScript type stripping. | Node 24 runs .ts directly and browsers resolve bare specifiers via import maps, so a bundler buys nothing here and costs hundreds of licence-register entries (D-039). The whole Node surface is typescript and @types/node, neither of which ships. | Approved 24 Aug 2026 |
| D-050 | TypeScript contract types are generated from the exported JSON Schema by a Python tool, committed, and drift-checked. Canonicalisation and digests are hand-written on both sides and verified against one shared vector file. | Generation prevents the browser lab and the runner from silently disagreeing about a field name. The vectors prove the two behavioural implementations agree rather than assuming it: removing .sort() from the TypeScript serialiser fails the suite immediately. | Approved 24 Aug 2026 |
| D-051 | Reimplement the Real-ESRGAN generator architecture rather than installing the official `realesrgan` package, and load the official published weights into it. | The official package hard-depends on `gfpgan`, a face-restoration model. POC-006 requires that face restoration is never silently invoked, and a dependency that can reconstruct a face is not made safe by our choosing not to call it. Correctness is verified rather than asserted: `load_state_dict(strict=True)` means a wrong architecture cannot load the official checkpoint at all. | Approved 24 Aug 2026; see ADR-0005 |
| D-052 | Register Real-ESRGAN's training datasets as first-class licence components, and let the weights inherit their restrictions. The composite resolves to `unknown`, not to the code's BSD-3-Clause. | The repository's BSD LICENSE covers source code; no weight licence is stated anywhere. The published weights derive from DIV2K, whose ETH Zurich page states the data is 'made available for academic research purpose only' with third-party copyright in the images. Whether trained weights inherit training-data restrictions is legally unsettled - which is a product-owner and counsel question, not an engineering one. A permissive code licence must not launder restricted weights. | Approved 24 Aug 2026; commercial question escalated; see ADR-0005 |
| D-053 | Gate A (commercial) and Gate B (supply chain) are independently evaluated, and satisfying one never implies the other. | POC-006 is the first real demonstration: recording the weight digests satisfied Gate B and opened research use, while Gate A still refuses every commercial purpose. A POC-002 test that asserted nothing could ever execute was replaced - by POC-006 it had become an assertion that the gate never opens, which would make the gate decorative. | Approved 24 Aug 2026; see ADR-0005 |
| D-054 | The processor-contract conformance suite must exercise a successful processing path, not only failure paths. Its probe asset is a real decodable image. | The probe had been a short ASCII string since POC-001, so every image processor refused it at inspection and every check gated on success - deterministic output, measurement, cleanup after a real write - was skipped in silence. The suite reported eleven passing checks while grading only half the contract. Found by using it for its intended purpose in POC-006. | Approved 24 Aug 2026; see ADR-0005 |
| D-055 | Record a per-call, process-isolated-equivalent memory figure alongside peak RSS (`MemoryUsage.python_peak_delta_bytes`). Contract 1.1.0 to 1.2.0, additive. | Peak RSS is a process-lifetime high-water mark. The first AI-versus-resize comparison reported 410 MB for both, because both ran in one process - true of the process, false of the Lanczos resize, and any reader would have drawn the wrong conclusion. A single trustworthy per-call total needs process isolation, which is what the container definition is for. | Approved 24 Aug 2026; see ADR-0005 |
| D-056 | Third-party source may be vendored verbatim when reimplementing it would risk a silent numerical error, provided it is attributed, pinned by commit and digest, states its modifications, and is excluded from our formatter, type checker and coverage but not from the import guards. | SwinIR's architecture is 867 lines of Swin Transformer. A reimplementation could load the published checkpoint with strict=True and still be subtly wrong - a mismatched window-partition order has the right shapes and the wrong output, and nothing in the loading path would notice. An attributed copy cannot fail that way, and Apache-2.0 expressly permits it. Contrast POC-006, where reimplementing was right because the official package dragged in a face-restoration model. | Approved 25 Aug 2026; see ADR-0006 |
| D-057 | Add `ai_denoise` and `jpeg_artifact_repair` as AI-family operations, and write `ADVERTISED_OPERATIONS` out explicitly instead of deriving it from the family map. Contract 1.2.0 to 1.3.0. | PRODUCT_REQUIREMENTS section 10 lists 'advanced denoise' as an AI capability, but the only `denoise` kind is in the STANDARD family - correctly, since a median filter must never route to a model - which left AI denoise inexpressible. Separately, the derived advertised set meant adding an operation so a benchmark could measure it would have advertised it to customers and attached a D-040 obligation to it, as a side effect of an enum. Measuring is not promising. | Approved 25 Aug 2026; see ADR-0006 |
| D-058 | Gate B's execution-shaped requirements (pinned version, weight digest, weight format, network disabled) do not apply to `dataset` components. `official_source` still does, and the dataset's disposition still propagates through Gate A. | Nothing here downloads, unpickles or executes a dataset; it is registered so the restrictions it carries reach the weights trained on it. 'Pin the version you execute' has no answer for something never executed, and the datasets already registered passed only because a plausible year had been typed in - a habit that looks like a control. Surfaced by WED, whose official page now 404s. | Approved 25 Aug 2026; see ADR-0006 |
| D-059 | Implement PSNR and SSIM directly on numpy, name the SSIM variant in every report, and compute no winner: the comparison document carries a `winner` field that is always null with a note explaining where the answer comes from. | POC-007 requires that no winner be declared from objective metrics alone, and the way to satisfy that is to have no code that could. The first real run justified it: PSNR ranked Real-ESRGAN above SwinIR and SSIM ranked them the other way, so any numeric verdict would have been a choice of metric presented as a finding. The variant is named because 'SSIM' alone does not identify a number. | Approved 25 Aug 2026; see ADR-0006 |
| D-060 | Gate B controls (digest verification, restricted unpickling, the network guard, tensor conversion) live in exactly one module shared by every AI adapter, and the pinned file size is verified before the digest. | POC-006 wrote them inline when there was one adapter. Two copies could drift, and a control that applies to one model and quietly not the other is the failure nobody notices. The size check also caught a real defect: the recorded byte count for RealESRGAN_x2plus was wrong and was never read by any code path - a dead field that reads like a check is worse than no field. | Approved 25 Aug 2026; see ADR-0006 |
| D-061 | Blinding closes every channel that correlates with the producer, not only filenames: opaque labels, a flat directory, a keyed shuffle, stripped metadata, and re-encoding plus padding so every item is the same size on disk. | The acceptance criterion says filenames and UI, but file size would have defeated the exercise on its own - the three POC-007 candidates wrote 2,630, 83,125 and 87,651 bytes, so any file browser identifies the deterministic baseline before a reviewer opens anything. The residual channel that cannot be closed - the images genuinely differ - is documented rather than hidden. | Approved 25 Aug 2026; see ADR-0007 |
| D-062 | A review item carries two identifiers: an opaque label the reviewer sees, and a sealed entry holding run, result, processor version and weight digest. Ordering comes from a seed-keyed shuffle whose seed lives in the sealed half, and the CLI refuses to write the sealed key inside the package directory. | Blinding and traceability pull in opposite directions and one identifier cannot do both. Deriving the label from a digest of the provenance looks opaque and is trivially reversible with three candidates. `random` is banned for reproducibility, and is not needed: sorting by sha256(seed || key) is a permutation that is reproducible from the seed and unguessable without it. | Approved 25 Aug 2026; see ADR-0007 |
| D-063 | Critical failures are a separate, dominant channel from scores. One reviewer raising one failure fails the item regardless of its scores, and any disagreement about a failure - or an overall-score gap of 2 or more - flags a third review rather than being averaged. | Folding a failure into the mean is exactly the operation that lets an appealing result outvote its own unacceptability. Demonstrated on the first real run: the highest-scoring item (4.62) was the failed one, because one reviewer noticed a changed digit. Averaging 2 and 4 into 3 manufactures a consensus that does not exist. | Approved 25 Aug 2026; see ADR-0007 |
| D-064 | Review verdicts store score sums and counts, never a mean. Means are derived for display only. | A committed artifact holding a float invites drift unrelated to what is being measured - the same reasoning that makes the canonicaliser reject floats, applied to a document that is diffed rather than digested. | Approved 25 Aug 2026; see ADR-0007 |
| D-065 | Batch state lives in an append-only journal on disk, fsynced after every item, not in the calling process. The journal is the run; the returned object is a convenience. | "Closing the client does not stop cloud work" is a statement about where state lives. Holding a run in a local variable loses every completed result when the process is killed at item 47 of 50. fsync rather than flush because the difference only shows up when the machine loses power rather than the process losing its terminal - which is the case a durability claim is about. | Approved 25 Aug 2026; see ADR-0008 |
| D-066 | A truncated final journal record is discarded and the rest of the file is used. The count of discarded records is reported, never swallowed. | A process killed mid-write leaves a partial line. Losing that one item is recoverable by reprocessing it; refusing to parse the file would lose the forty-nine before it as well. Reporting the discard matters because a resume that silently reprocessed a corrupt record would be correct but would hide the fact that a process died. | Approved 25 Aug 2026; see ADR-0008 |
| D-067 | Resume keeps outcomes that concluded (succeeded, failed) and re-attempts outcomes that never ran (skipped, cancelled). Resume is not retry. | Found by a failing test: a declared asset with no local file is SKIPPED, not FAILED, because the processor never ran - and an asset can be absent because it is in external storage and has not been fetched yet. Treating that skip as final would strand it forever on a condition already fixed, and on a batch of fifty nobody would notice which one. The distinction is whether it was attempted, not whether it worked. | Approved 25 Aug 2026; see ADR-0008 |
| D-068 | Begin building the customer-facing application alongside the POC, starting with the image workspace: a local service exposing the same processors the benchmark measures, and an interface that offers every advertised operation with standard editing as the default path and AI as an explicit, separately-styled choice. Refines D-036 rather than replacing it - the POC tasks and their gates continue unchanged. | Product-owner direction, 25 Aug 2026: "the application should support all types of users and all types of works and all types of operations" and "build user-friendly UI". The POC has proven the machinery; what was missing was the surface a customer meets. Building the app on the benchmarked processors rather than a parallel implementation is what keeps every figure in data/reports a statement about code that actually runs. | Approved 25 Aug 2026; see APP-001 |
| D-069 | Write the PDF engine rather than adopt one. Standard library only, and a JPEG is embedded byte-for-byte via DCTDecode rather than re-encoded. | Pillow's PDF export was tested first, not dismissed: it does pass JPEG through untouched, but has no concept of text, vector shapes or CMYK, all of which PRODUCT_REQUIREMENTS section 19 requires. reportlab and fpdf2 are capable and are permanent licence-register entries under Gate A. The passthrough is the quality decision that matters: re-encoding spends a second lossy generation, which on flat colour and hard line work shows as ringing along every edge - exactly the 'minute lines' a textile print must keep. Measured: an 8-page sheet of 6 designs is 1,319,995 bytes from 1,314,200 bytes of source. | Approved 25 Aug 2026; see APP-002 |
| D-070 | Write the raster-to-vector tracer rather than adopt one: boundary following, corner detection, Bezier fitting and SVG/PDF emission are implemented in `ipw.vector`. | potrace and autotrace are the two mature options and both are GPL, which would decide the licence of the whole product rather than of one feature - a far larger consequence than the usual Gate A dependency question. Vectorising is not a textile feature: a sign-writer needs a cut path, a laser or waterjet cannot read pixels at all, an embroiderer needs closed shapes, a screen printer needs one separation per colour, and a marketing team has a logo that exists only as an old JPEG. Upscaling cannot serve any of them - more pixels are still pixels. Quality is measured rather than asserted: a traced 150px-radius circle reproduces to 0.70px of the true circle, and a square returns exactly four straight sides with its corners on the original coordinates. | Approved 25 Aug 2026; see APP-003 |
| D-071 | Redaction deletes content and then verifies the result by reading the finished file back. Characters are removed from the content stream one at a time, pixels under the box are overwritten inside any image, overlapping annotations are dropped, and the document is rebuilt rather than appended to so no earlier revision survives. The black rectangle is drawn last, as a mark for the reader. | Drawing a box and stopping is what most tools do, and the failure is silent: the page looks redacted and the text is still selectable, copyable and indexable. Rebuilding rather than appending closes the second route - several published redaction failures were undone by reading the revision underneath, not by selecting text. Verification is what turns the promise into a fact: `verify()` re-extracts and reports any phrase still present, and the API returns that as a boolean rather than prose. Per-character removal is deliberate - dropping the whole show-text operator is far easier and deletes the sentence around the name. | Approved 25 Aug 2026; see APP-004 |
| D-072 | Any image being replaced is removed from the page *before* the page is copied, via `page_body_without_xobjects`, rather than swapped in the copied resources afterwards. | Found by measurement, not review: compression was returning files that had grown. Copying a page copies the image it references, so replacing the resource entry afterwards leaves the original in the file - unreferenced, invisible in every viewer, and readable by anything that walks objects instead of pages. In compression that is a wasted megabyte. In redaction it is the original unredacted scan sitting inside a document certified as safe to release. Every redaction test passed while this was live, because they asked the page for its image and got the painted one; the test that catches it enumerates every object in the file, which is what an adversary does. | Approved 25 Aug 2026; see APP-004 |
| D-073 | Compression takes a target size in megabytes and walks a fixed ladder of (DPI, quality) settings from best downward, stopping at the first that fits. A target that cannot be met is reported as a miss with the smallest honest result, never as a success. | The request is never 'compress this' - it is 'the portal will not take anything over 10 MB'. Offering low/medium/high makes the customer guess and re-guess. Walking downward rather than jumping to the smallest means a file needing a mild reduction does not come back looking like a fax. Reporting a miss matters most: a customer who believes their file is under the limit finds out at the upload form, having already been told it was fine. Measured on a six-page 300-DPI scan: 2.91 MB to 0.26 MB at 72 DPI, with the delivered DPI reported alongside so the cost is visible rather than inferred. | Approved 25 Aug 2026; see APP-004 |
| D-074 | Split OCR into the recogniser and the text layer, and build the text layer first. `ipw.pdf.textlayer` takes words with boxes and writes them over a scan in invisible render mode; the recogniser is a Protocol with one method. | The engine is the part that needs a licence decision and the part that is interchangeable; the geometry is the part that decides whether the result is any good, and it is ours either way. Splitting them meant the whole feature could be built and tested to exact tolerances with hand-written words and no engine installed - measured drift between the invisible text and the ink is 0.00pt. It also means changing engine later is a swap rather than a rewrite. The payoff is concrete: once a scan carries a text layer, redaction by phrase works on it, so a name is typed once instead of drawn on every page. | Approved 26 Aug 2026; see APP-005 |
| D-075 | Adopt Tesseract as the recogniser, called as a subprocess rather than through `pytesseract`, and record it as `review_required` with version 5.4.0.20240606 pinned and the English model's SHA-256 recorded. | Chosen for provenance over accuracy: its models are trained on synthetic renderings of fonts rather than scraped documents, so the failure behind O-013 - permissive code sitting on research-only training data - does not arise by construction. RapidOCR and EasyOCR are stronger on photographs and carry that question unanswered; Surya was excluded for revenue conditions, the CodeFormer trap. A wrapper library would be a permanent register entry buying forty lines of subprocess and TSV parsing, when the binary is the real dependency either way. `review_required` rather than approved is the honest disposition: the Apache-2.0 position was read, not verified against source, and D-058 was written about exactly that habit. Measured: 34 words off a scanned letter in 0.9s, after which a name is removed by typing it. | Approved 26 Aug 2026; see APP-005 |
| D-076 | Batch processing loops in the browser, one request per image, with the server exposing `/api/batch` for scripts rather than for this screen. A result is only counted as finished when the response says `ok: true`. | One request per image makes the progress real rather than a guess, attaches a failure to the file that caused it, and lets three failures be retried without re-running the forty-seven that succeeded. A single request for the whole batch is easier to write and gives the customer a spinner and no information for four minutes. The `ok: true` check is not defensive detail: `/api/process` refuses a corrupt file by *returning* a failure rather than raising, so an earlier version counted a file of random bytes as completed and put it in the ZIP - a silent failure worse than the one it hid. Section 13's ceiling of fifty is enforced with the number in the message, because accepting sixty and dying halfway is worse than refusing. Archive names are deduplicated and stripped of path components: two folders each containing `scan.jpg` is ordinary, and a ZIP entry called `../../evil.png` is a weapon. | Approved 26 Aug 2026; see APP-006 |
| D-077 | Documents use the same batch screen as images rather than a second one, and a mixed drop is refused instead of guessed at. The document operation list is deliberately short: compress, redact, recognise, stamp, turn, check-searchable. | The grid, the progress, the retry and the archive are identical work; two screens would drift and the second would be the one that stopped getting fixes. The short list is the honest part - splitting at page four means something different in every document and merging is one output rather than fifty, so neither belongs on a screen whose promise is 'the same thing to all of them'. A mixed drop is refused because silently taking the six images and ignoring the four PDFs is the same failure as taking the first file and ignoring the rest, only harder to notice. A batch redaction where the words were not found is marked *failed*, not completed: assuming a name was removed because nothing complained is exactly how documents get released with it still in. Measured end to end: six scans recognised and a name removed from all of them, each verified against the bytes, with a corrupt seventh isolated throughout. | Approved 26 Aug 2026; see APP-006 |
| D-078 | Numbering returns the number it stopped at, and the batch threads that into the next document rather than restarting each file at one. | A disclosure bundle is sixty files that a court refers to as one thing - 'see ABC-000412'. If each file restarts there are sixty page 412s and the citation means nothing, so `next_number` is not a convenience, it is the feature. The count survives a failure in the middle: a corrupt file between two good ones neither restarts the sequence nor skips a block of numbers, which is what a bundle certified as complete has to be able to claim. Positioning is measured from each page's own box rather than an assumed A4, because a bundle holds a scan, a plan and a letter and an assumed width puts the mark off two of them. | Approved 26 Aug 2026; see APP-006 |

## Rejected or corrected interpretations

| Item | Resolution |
|---|---|
| “All images must use server CPU/GPU.” | Rejected. Use automatic hybrid local/cloud processing with Advanced override. |
| “Browser JavaScript only needs the database backend.” | Rejected for the complete product. Browser is suitable for previews/light work; durable, professional, batch and AI outputs require cloud paths. |
| “Real-ESRGAN is the final recommended model.” | Corrected. It is an initial benchmark baseline only. |
| “Hugging Face models versus Real-ESRGAN.” | Corrected. Hugging Face is a hub/hosting platform; comparisons must name a specific model and task. |
| “Hybrid means using Codex/Cursor/Claude.” | Corrected. Coding agents build the app; runtime hybrid refers to browser, cloud CPU/GPU, self-hosted models and optional external providers. |

## Change-control rule

An AI coder may identify a new trade-off, but it must not change an Approved decision silently. It must propose the change, explain evidence and impact, and obtain product-owner approval. Record approved changes as a new decision-log entry rather than rewriting history without explanation.
